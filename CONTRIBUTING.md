# Contributing to felis

This guide is for humans contributing code, docs, or configuration to felis. Agent-specific notes live in
[AGENTS.md](AGENTS.md); the design docs are the source of truth for feature decisions (`docs/README.md` is the map).

## Development environment

The Nix flake at the repo root is the single source of truth for the toolchain (nightly Rust, runtime libs for
wgpu/winit, formatter, and pre-commit hook). The rationale lives with the configuration, in `flake.nix` and
`dev/flake-module.nix`.

```sh
nix develop          # dev shell — installs .git/hooks/pre-commit automatically
nix fmt              # treefmt
just check           # local PR gate: fmt-check + clippy (native and wasm32 portable core) + prose + skills + nextest + docs links + cargo-deny + proto-compat + tool self-tests
just --list          # all recipes (fuzz, kani, bench, snapshot, …)
```

- Do not add `rust-toolchain.toml`, `cargo install ...`, `.editorconfig`, or ad-hoc tool-version pins. The flake owns
  these surfaces.
- `.pre-commit-config.yaml` is a Nix-store symlink; hooks are defined in `dev/flake-module.nix`.
- `just check` mirrors CI (`.forgejo/workflows/pr.yml`). The `proto-compat` half needs `origin/main` fetched.

## Workflow

- `main` is protected; direct pushes (including force-pushes) are disabled. All changes go through feature branches and
  pull requests. Feature branches may be rebased and pushed with `--force-with-lease`.
- One logical change per commit. A multi-doc cascade that belongs to one decision (for example, a milestone renumbering)
  may be one commit.
- Before claiming a doc change "consistent," grep for the changed term across `docs/`.
- The repo uses **Forgejo Actions**, not GitHub Actions. Be careful when touching workflow files.

## Commit conventions (Scoped Commits)

felis follows [Scoped Commits](https://scopedcommits.com/) (`<scope>: <description>`) with the project-specific scopes
below.

### Format

```
<scope>: <description>

[optional body]

[optional trailer(s)]
```

- **Subject line**: `<scope>: <imperative>`, at most 72 characters. Start the description with an imperative verb,
  lowercase, no trailing period. Example: `client: middle-click pastes from PRIMARY (Linux convention)`.
- **Scope**: the subsystem, area, or module the commit touches. Scope is required and is the most important part of the
  message for scanning `git log`. See the valid scopes table below.
- **Body** (optional but encouraged): explains **why**, not what. The diff already shows what changed. State the
  motivation, the constraint being worked around, or the rejected alternative and why it was rejected. A why that would
  otherwise become a code comment or a doc paragraph belongs here: the source keeps only why-nots and invariants, the
  docs keep only decisions that pass the `doc-cascade` skill's record gate.
- **Trailers** (optional): `Signed-off-by`, `BREAKING CHANGE:`, and similar, as needed.
- **Reverts, merges, and other special commits** may use free form (for example, `Revert "..."` as generated by
  `git revert`).

### Valid scopes

| Scope         | Area                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------- |
| `cli`         | `felis-cli` crate, the `felis` front-door binary                                               |
| `client`      | `felis-client` crate, the winit GUI frontend                                                   |
| `client-core` | `felis-client-core` crate, shadow screen, config, `connect_or_spawn_daemon`                    |
| `daemon`      | `felis-daemon` crate, session pool, IPC server                                                 |
| `grid`        | `felis-grid` crate, cells, scrollback, image store                                             |
| `protocol`    | `felis-protocol` crate, `felis.proto`, frame layout, version constants                         |
| `pty`         | `felis-pty` crate, PTY backends                                                                |
| `render`      | `felis-render-wgpu` crate, GPU pipeline, atlas                                                 |
| `shaping`     | `felis-shaping` crate, swash shaper, font fallback                                             |
| `transport`   | `felis-transport` crate, framing, socket/pipe, SSH carrier                                     |
| `vt`          | `felis-vt` crate, VT parser, dispatch                                                          |
| `manual`      | User-facing docs quadrants: `docs/tutorials/`, `docs/how-to/`, and user-facing reference pages |
| `docs`        | Documentation tree when no narrower scope fits (or cross-quadrant doc cascades)                |
| `skills`      | Agent skills (`skills/felis`, `.agents/skills/`)                                               |
| `ci`          | CI workflows (`.forgejo/workflows/`)                                                           |
| `nix`         | Nix flake, home-manager module, package definitions                                            |
| `deps`        | Dependency bumps (often generated by Renovate)                                                 |
| `treewide`    | Tree-wide or cross-cutting change that does not fit one scope                                  |

Guidance:

- Prefer the narrowest scope that covers the change. A change to the parser belongs in `vt:`, not `treewide:`.
- For a change touching two scopes, either pick the more general parent, list both comma-separated
  (`daemon, client: ...`), or use `treewide:` if it truly spans the tree. If no scope fits cleanly, treat it as a
  special commit and write a clear description.
- Keep scope lowercase; use `client-core` (with hyphen) as in the crate name, not `client_core`.

### Examples

- `daemon: evict oldest images on over-budget transmit`
- `protocol: add typed daemon stop and draining state`
- `cli: add felis daemon stop`
- `vt: ignore Kitty graphics placeholder in selection`
- `docs: freeze inert foreign client section for 1.0`
- `deps: update Rust crate wgpu to v30`

Body example:

```
daemon: evict oldest images on over-budget transmit

The per-session image budget is 256 MiB (REQ-1008). Rejecting a
large transmit at the wire would break producers that batch a yazi
preview with a single APC. Evicting the oldest images keeps the
session usable and matches kitty's behaviour. Rejected alternative:
raising the cap, which would grow steady-state memory without fixing
the batch case.
```

## Documentation

- `docs/README.md` defines the Diataxis quadrants and twin pairs (reference vs. explanation). Follow it when adding or
  moving a page.
- Record design decisions inline in the owning explanation doc (rationale, rejected alternatives, "Revisit if ...").
  Reference (`docs/reference/...`) holds only normative facts.
- History belongs to `git log` (and `CHANGELOG.md` for user-affecting surfaces), never to the docs.
- Run the `doc-cascade` checklist before declaring a doc change done: update the twin, grep the changed term across
  `docs/`, regenerate schemas/contracts when touched, and check the non-doc mirrors (`README.md`,
  `skills/felis/SKILL.md`, `nix/hm-module.nix`, `CHANGELOG.md`).

## Workspace policy

`docs/reference/workspace.md` governs the crate map, dependency direction, filesystem layout, and build/platform matrix.
Lint, edition, MSRV and the `unsafe_code` policy are defined by `Cargo.toml` and `clippy.toml`; a doc names those files
rather than repeating a value out of them. Audited `unsafe` relaxations are `#[allow(unsafe_code)]` sites with
`// SAFETY:` comments. Consult them before touching `unsafe`.
